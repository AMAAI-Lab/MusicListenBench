Submit a result

Score your model and open a pull request in the GitHub leaderboard repository. Merged results appear on the leaderboard and the Hugging Face Space.

  1. Run the official evaluation

    Get the Hugging Face dataset and use the model evaluation code on GitHub to answer the 3,000 rendered test items (1,000 clean, 1,000 FLIP and 1,000 STAY). Use only the training split for benchmark training.

    Write one JSON Lines file with model metadata on the first line and one item ID and answer (‘A’ or ‘B’) per line after that. See the example submission and the scoring script for the format. Missing or invalid answers count as wrong.

    Run the scorer from a checkout of the release branch. Replace /path/to/submission.jsonl with your file path.

    git clone --depth 1 --branch release https://github.com/AMAAI-Lab/MusicListenBench.git MusicListenBench-eval
cd MusicListenBench-eval
python -m musiclistenbench.scoring.score_submission /path/to/submission.jsonl

  2. Add one row per model and method

    Append a row to leaderboard.csv in your fork of the leaderboard repository. Report percentages to one decimal place and set verified to no for maintainer review.

    type,model,organization,model_url,access,domain,params_b,method,melody,rhythm,timbre,harmony,overall,acc_fs,miss_rate,false_flip_rate,a_rate,real_melody,real_rhythm,real_timbre,real_harmony,real_overall,real_acc_fs,real_miss_rate,real_false_flip_rate,real_a_rate,readout,verified,submitted_by,date,source_url,benchmark_version,notes
model,My-Audio-LLM,My Lab,https://example.org/my-model,open,general,7,zero-shot,60.0,55.2,66.8,52.0,58.5,57.6,40.1,44.7,52.0,,,,,,,,,,logprob,no,@your-github,2026-10-01,https://example.org/my-model/evaluation,1.0,

    The first four score columns are clean accuracy per task, overall is clean accuracy on all 1,000 clean items, and acc_fs, miss_rate, false_flip_rate and a_rate are FLIP/STAY accuracy, miss rate, false-flip rate and the share of ‘A’ answers on the clean items. The same nine columns with a real_ prefix hold the scores on the real-recordings test set (600 clean and 1,200 FLIP/STAY items); leave them empty if you did not run it. domain is music for a model built specifically for music understanding, which is listed in its own section, and general for any other audio LLM. method is zero-shot, or how you used the training split (for example GRPO (LoRA)); readout is logprob or generated.

  3. Open a pull request

    Run python scripts/validate.py leaderboard.csv from your leaderboard checkout before opening the pull request. GitHub runs the same check on the pull request.

  4. Maintainers review and merge

    Maintainers re-score your submission file with the same script. A row stays marked self-reported until they reproduce the numbers, and then verified is changed to yes.
